# SimpleChat P2P

**Tauri v2 + React (TypeScript) + Rust (`iroh`)** で構築された、**DesktopMate風透過オーバーレイUI** と **ハイブリッド鍵交換・フルメッシュP2P・マッチングチャット** を備えたデスクトップチャットアプリケーションです。

## 主な特徴

1. **DesktopMate風の透過オーバーレイ ＋ 通常履歴ウィンドウの2画面構成**
   - **オーバーレイウィンドウ (`overlay`)**: 背景透過・枠なし・常時最前面（Always on Top）でデスクトップ上にマスコットが常駐。ドラッグで自由な位置へ移動でき、送受信したチャットは吹き出しとしてポップアップして **約5秒後にフェードアウトして消えます**。マスコット下のミニ入力バーからそのまま即返信も可能です。
   - **履歴＆接続設定ウィンドウ (`main`)**: オーバーレイ上で消えたメッセージも含め、全チャット履歴を自動保存・次回起動時にも引き継ぎます。**「👤 1対1（相手ごと）」「🏠 グループ（ルームごと）」「📡 マッチングチャット（マッチング回ごと）」** に自動でスレッド分類され、上部タブからいつでも切り替え・ログ出力・個別消去が可能です。
2. **ハイブリッドP2P通信（管理サーバ ＋ QUIC/Ed25519 フルメッシュE2E暗号化通信）**
   - **管理・鍵交換サーバ (`directory-server`)**: ユーザID（`@alice` 等）と Ed25519 公開鍵（`NodeId`）・最新接続チケットを **Ed25519電子署名検証付き** で登録・管理し、なりすまし登録や公開鍵すり替え（MITM）を防止します。
   - **1対1 ＆ フルメッシュ・グループチャット**: オンラインユーザ一覧やグループルーム一覧から接続でき、**チャット本文は管理サーバを一切経由せず Iroh (QUIC + TLS 1.3) でピア間を直接暗号化通信**します。ルーム作成時には **🔑 合言葉（パスフレーズ）** による参加制限も設定可能です。
   - **📡 マッチングチャット（同一LAN自動探索）**: 管理サーバなしでも、同一ネットワーク内でマッチングをONにしている相手（合言葉タグ一致または「誰でも」）を Ed25519 署名付き UDP ブロードキャストで自動発見し、承認後にP2Pチャットを開始できます。
   - **手動チケット接続も併用可能**: 接続チケット文字列のコピー＆ペーストだけでP2P接続・グループ追加ができます。
3. **Docker完結のLinux / Windows両対応ビルド**
   - ホスト環境を汚さず、Dockerコンテナ上で自動テスト・Linux向けビルド・Windows向けクロスビルド（`cargo-xwin` + `NSIS`）を実行できます。

## ネットワーク・ポート要件（TCP / UDP）

管理サーバやクライアントを運用する際の使用ポートとプロトコルは以下の通りです。

| 役割 | ポート番号 | プロトコル | 開放が必要な場所・備考 |
| :--- | :--- | :--- | :--- |
| **管理サーバ (`directory-server`)** | `3100` | **TCP** (`3100/tcp`) | **管理サーバを動かすマシン / VPS**<br>HTTP REST API（ユーザ登録・オンライン一覧・公開ルーム一覧）として使用します。サーバ側では **`3100/tcp` のみ**開放すれば動作します。 |
| **マッチングチャット探索** | `41920〜41939` | **UDP** (`41920-41939/udp`) | **同一LAN内の各クライアントPC**<br>同一ネットワーク内の相手を自動発見するための Ed25519 署名付き UDP ブロードキャストに使用します。 |
| **P2Pチャット本通信 (`iroh` QUIC)** | 動的ポート (自動) | **UDP** | **各クライアントPC**<br>QUIC (TLS 1.3) によるピア間直接通信に使用します（NAT越えホールパンチング・リレー自動対応のため、通常はルータ等の手動ポート開放は不要です）。 |

## 使い方（Dockerによるテスト・ビルド・起動）

### 1. 自動テストの実行
フロントエンドのビルド、管理サーバのEd25519署名検証テスト、およびRustのIroh P2P 2ノード間通信テストを実行します：
```bash
docker compose run --rm test
```

### 2. 管理サーバ（Directory Server）の起動
ユーザ登録・公開鍵自動交換・オンライン一覧を使う場合は、バックグラウンドで管理サーバ（ポート `3100`）を起動します：
```bash
docker compose up -d directory-server
```

### 3. Linux向けビルドと起動
```bash
docker compose run --rm build-linux
```
ビルド完了後、以下のファイルが `./artifacts/linux/` に出力されます：
- `artifacts/linux/simple-chat` （Linux実行バイナリ）
- `artifacts/linux/*.deb` （Debian/Ubuntuパッケージ）

起動するには：
```bash
./scripts/run-linux.sh
```
（同一PC上で2つ同時に起動して1対1のP2P通信テストを行うことも可能です）

### 4. Windows向けクロスビルド（`.exe` / NSISインストーラー）
Linux上のDockerから Windows (`x86_64-pc-windows-msvc`) 向けの実行ファイルとインストーラーを生成します：
```bash
docker compose run --rm build-windows
```
ビルド完了後、以下のファイルが `./artifacts/windows/` に出力されます：
- `artifacts/windows/simple-chat.exe` （Windowsポータブル実行ファイル）
- `artifacts/windows/*-setup.exe` （Windows NSISインストーラー）
